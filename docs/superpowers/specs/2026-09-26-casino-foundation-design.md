# Casino 文本、菜单与运行基础优化设计

状态：用户已批准并执行。实现与验证结果见 docs/verification.md；客户端画面及操作体验仍由用户验收。

## 目标与边界

在 Casino 内完成一套可供 Tabletop 后续参考的文本、菜单和显示实体基础实现。主要目标是可编辑语言稳定、安全地显示，错误配置有可定位的反馈，菜单失效时不执行操作，空闲机器减少无效工作。

- 工作区仅为 `server-casino/` 和 Casino 专用验证文件；不修改 Tabletop。
- 保留 Java 25、Paper/Purpur 26.2、独立安装、原生 Dialog、原版机器模型和按钮布局。
- 保留游戏规则、随机结果、免费练习资金行为、现有模型定义与存档语义。
- 保留可选经济及外部模型接口；本轮不建立公共运行时插件或跨仓库依赖。
- 交付本地 JAR、源码、测试结果和 Tabletop 对齐说明，并同步 GitHub。发布 Release 仍需用户另行同意。

## 已核实的现状

1. `Language.message` 先进行字符串占位符替换，`PaperMenus.text` 再解析 MiniMessage；动态内容与模板没有类型边界。
2. `PaperMenus.text` 手工替换小写 `&` 颜色码，未完整处理 `§`、大写代码及旧颜色重置语义。
3. `Language.readFile` 在 YAML 读取异常时回退，但 `strings` 静默跳过非字符串，未校验命名占位符。
4. `Language.load` 创建目录或复制内置文件的 I/O 失败仍可阻止启动；目前没有语言热重载。
5. `CasinoMenus.Page` 用 Java 生成临时 YAML，`PaperMenus` 再读取；内部菜单没有使用外部布局的需求。
6. 回调已绑定玩家、单次使用、超时与当前会话；机器设置还会复查权限、机器存在性和管理距离。应保留这些检查并补回归。
7. `PaperMenus` 对文字恰好为 `Close` 或 `关闭` 的按钮进行特殊改写。
8. `VanillaDisplay.sync` 已跳过未变化的属性写入，但仍在每次同步中遍历所有子实体。
9. 按压按钮在四个 tick 内重复写相同姿态；机身文字按字符串长度估算尺寸。
10. 区块加载会调度扫描所有保存记录；是否需要索引须根据规模测量决定。

## 一、统一文本接口

### 契约

- `Language.text(key, pairs...)` 保留为纯文本接口，供日志、异常、规则状态等使用；不通过控制台文本反推菜单动作。
- 增加返回 Adventure `Component` 的显示接口。模板中的 MiniMessage 样式被解析；普通参数以纯文本插入，显式 Component 参数保持结构，不再次解析为标签。
- 占位符继续使用 `{name}`，保留现有语言文件目录、消息键和命名参数。
- 日志使用纯文本；菜单、聊天、ActionBar、可编辑实体标签统一使用 Component 接口。
- 文本中的动作能力与业务回调分离。菜单按钮和可点击正文的动作只由代码提供，普通动态参数不得生成动作。
- 定义并测试允许的样式标签；语言文本不获得任意命令执行能力。保留现有颜色、粗体、斜体、下划线等显示能力。

### 旧颜色配置

为现有 `&`、`§` 配置提供明确兼容入口，正确处理大小写和颜色对装饰的重置。新增内置语言统一使用 MiniMessage。混用格式制定确定性规则并在文档举例，避免持续增加零散的字符串替换。

### 验收

动态值含 `<red>`、旧颜色码、反斜杠、花括号、换行时仍作为数据显示；参数不会递归替换。聊天和菜单渲染结果一致；语言模板不能替换业务动作。

## 二、语言校验与重载

- 以 JAR 内英文为消息键和占位符基准。
- 缺失词条继续逐项回退；非字符串、未知键、占位符拼错、格式错误产生包含文件和键的诊断。
- 允许翻译省略不需要显示的参数，但拒绝引入模板没有声明的参数；保留现有自定义短文案。
- 首次启动可用词条覆盖基准，错误词条回退。文件创建失败时使用内置英文并报告具体路径，不改写用户文件。
- 增加 `/3dcasino reload-language`，控制台和管理员可用，补全按权限提供。重载先完整读取并校验；有错误时保留上一份有效语言。
- 成功重载使旧菜单会话失效，后续消息使用新语言；现有机器的文字刷新，不重建整个机器、不终止回合、不改变碰撞布局。
- 缺键或同类配置错误集中报告，避免每次显示都重复刷日志。

## 三、菜单结构与会话

- 使用不可变菜单描述承载标题、正文、按钮、输入框和关闭按钮；这些文本直接使用 Component。
- Casino 内部移除 Java → 临时 YAML → Dialog 的转换和依靠文字内容改写关闭按钮的逻辑。
- 可编辑外部 YAML 布局作为适配层的接口设计写入对齐说明；Casino 本轮不凭空增加菜单布局配置功能。
- 回调统一保留：玩家绑定、当前会话、单次消费、超时、插件启用、菜单开关以及主线程执行。
- 机器操作继续在执行时校验权限、所有权、距离/世界、机器存在及忙碌状态。
- 超时时间维持现有 5 分钟；不为统一而改变有效交互时长。
- 关闭、重开、语言重载、退出和插件停止均清理会话。过期会话即使未被点击，也有明确清理路径。
- 输入长度、按钮宽度和列数在描述构造阶段校验，避免点击时才发现配置错误。

## 四、机器文字排版

- 测量解析后的可见文字，格式标签不计入宽度；考虑多行、Unicode 码点及宽窄字符。
- 沿用当前标签矩形与默认颜色，提供合理的宽度估算和最小字号策略，避免长翻译无限缩小。
- 优先使用标签区域内的换行或明确截断策略；不移动按钮或扩大模型遮挡范围。
- 原版字体宽度估算不承诺对玩家自定义字体资源包像素精确。说明这一限制并提供中英文长文本预览。

## 五、显示实体与交互性能

- 给静止且没有模型/变换/位置/发光变化的 `VanillaDisplay.sync` 增加快速返回，避免遍历子实体。
- 模型切换、零缩放恢复、发光变化、重载文字仍必须正确同步。
- 按压开始和结束时写入姿态，移除中间 tick 对相同姿态的重复设置；保持按压持续时间。
- 测量空闲和动画时的子实体访问、变换更新与生成/删除次数；以操作次数回归为主要依据，耗时测量作为参考。
- 审查多个机器的悬停检测和遮挡射线重复计算；只有测量显示收益且能保持选择语义时才共享结果。
- 审查区块恢复扫描；若规模测量证明有必要，按世界/区块索引保存记录，并测试跨区块机器的恢复与卸载。未达到收益门槛则记录结果，不添加索引复杂度。
- 不为了减少实体直接降低已经认可的圆角精度或移除模型部件。

## 六、额外逻辑审查

审查创建失败的清理、保存失败的内存一致性、恢复中的定义验证、重复点击、权限变化、插件关闭时的任务与会话生命周期。

只有确认的缺陷和有测量依据的浪费进入实现。存档仍采用先保存再更新内存的模式，保留原子替换；不以性能优化为理由异步并发写入交易存档，也不改写付款结果不确定时的处理规则。
